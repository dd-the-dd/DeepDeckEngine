# Coverage targets: quarantined tests

These tests prove real card behavior that the native Oracle compiler cannot
parse yet. Each one fails only because the Oracle grammar (or, where noted,
its diagnostic precision or reminder validation) does not cover the card's
text; they are not fixture or runtime failures. They stay compiled and are
quarantined explicitly instead of being deleted:

```rust
#[cfg_attr(
    not(feature = "coverage-targets"),
    ignore = "coverage target: <card>; see docs/coverage-targets.md"
)]
```

- Default `cargo test` reports them as `ignored` with that reason.
- `--features coverage-targets` (on `mtg-engine`, `deepdeck-oracle`,
  `deepdeck-engine-runtime` or `deepdeck-oracle-engine-contracts`) runs them
  as ordinary tests.
- CI runs them with `-- --ignored` in its `continue-on-error` quarantine step,
  so newly passing targets are visible without blocking the build.
- `scripts/check-coverage-targets.ps1` (run by CI) fails when the attributes
  and the table below disagree, and when any other `ignore` appears.

**Shrinking the quarantine.** When grammar lands for a card, delete the
`cfg_attr` attribute above its test and its row below, then run the test
normally. Do not add a row without the attribute, or the reverse.

The parser state is the first failing ability's committed diagnostic
(`automaton / state`) and `expected / found` token, recorded on the
branch `oracle/generalized-compiler` (PR #26). Since the structural-frame
change, an ability no family recognizes is no longer `unclaimed`: its frame
(`ability-frame`, `generic-trigger-program`, ...) commits the failure, and
the specialized family's state, when one applies, is kept as candidate
evidence. A row's recorded state therefore names the grammar gap; the live
committed diagnostic may name the enclosing frame instead.
